# コード分割規約

層の中でファイルをどう切るかを定める。層そのもの（何が何を知ってよいか）は
[アーキテクチャ.md](アーキテクチャ.md)が定める。本文書はその後段である。

## 1. 役割語彙

各クレートに置いてよいファイルの種類を、次の9役割で閉じる。「その他」の枠は無い。
分類できないコードが出たら、それは設計の誤りであり、語彙を拡張するかどうかをまず議論する。

| 役割 | ファイル名の例 | 中に書いてよいもの | 書いてはならないもの |
|---|---|---|---|
| 値型 | `object_identifier.rs` | newtype、不変条件の検査、その値に属する変換メソッド | 入出力、他の層の型 |
| ドメインモデル | `object_state.rs` | enumと網羅分岐、状態遷移 | 入出力、外部ライブラリの型 |
| エラー分類 | `storage_error.rs` | エラーのenumと表示、分類の判定 | 入出力、復旧処理 |
| 境界トレイト | `object_storage.rs` | トレイト定義と、その引数・戻り値の型 | 実装の詳細、外部プロセスの起動 |
| サービス | `asset_transfer.rs` | ドメインの手続き。依存はコンストラクタで保持する | JSONの形式、CLI引数の綴り |
| 外部境界 | `rclone_process.rs` | 子プロセス起動、ファイル入出力、外部コマンドの引数組み立て | ドメインの判断、上位層の型 |
| 外部表現 | `pc_config_toml.rs` | 外部のデータ形式（TOML・JSON）の形をそのまま写した型と、その導出マクロ | ドメインの判断、不変条件の検査、入出力 |
| コンポジションルート | `main.rs`, `assembly.rs` | 設定の読み込み、依存の配線、起動 | ロジック本体 |
| テスト | `tests/*.rs`, クレート直下の`tests/` | テストのみ | 本体のコード |

### 命名

- 意味を表す識別子は日本語で書く。受理条件はグローバルCLAUDE.md「日本語命名の受理条件」に従う。
- 外部仕様で固定される名前（Git LFSのJSONフィールド名、rcloneのCLI引数、TOMLのkey、
  Git設定のkey、Cargoのパッケージ名）は英語のまま保持する。
- ファイル名・ディレクトリ名・モジュール名は英語の`snake_case`とする。クレート名も英語である（Cargoの制約）。

## 2. 行数

グローバルCLAUDE.md「1ファイル100行の原則と分割の質」に従う。要点だけ再掲する。

- **1ファイルはコード行で100行以内、関数はコード行で50行以内。** 目標ではなく原則である。
- **数える対象はコードの行だけである。空行と、コメントだけの行は数えない。** 行末に書いたコメントはコードの行として数える。
- **100行に収めるためだけの分割を禁止する。** 分割したファイルは、名前を付けられる責務・概念・生成物を所有していなければならない。1つの流れを長さだけで切った一片を作らない。
- 未正当な分割の禁止は100行以内より優先する。統合した結果100行を超えるなら統合する。ただし**統合の結果として許す超過も150行を上限**とし、超過したファイルは冒頭コメントに「何と何を統合したのか」「分割すると流れの一片になること」を書く。
- **超過を許したファイルは [行数の例外台帳](行数の例外台帳.md) へ登録する。** `cargo xtask check-line-count` が台帳と実際の行数の両方を検査し、台帳にあるのに100行以内へ収まったファイルも違反として報告する。

## 3. 昇格経路

肥大化の圧力に対する逃し先を先に決めておく。判断コストをゼロにするための表である。

| 圧力（サイン） | 逃し先 |
|---|---|
| 関数が50行を超えた | 説明的な名前の関数へ分解し、原則として隣のファイルへ出す。同じファイルに残すのは10行未満の局所ヘルパのみ |
| 引数・戻り値に裸の`String`・`u64`・`PathBuf`が現れた | 値型を作って包む。個数によらない |
| `impl`ブロックが150行を超えた | 責務ごとに型を分割する |
| 1ファイルに役割が2つ以上同居した | 役割ごとにファイルを分ける |
| 1つの概念のファイルが3本以上になった | ディレクトリへ昇格し、`mod.rs`を集約点にする |
| 外部境界の型が上位層へ漏れ始めた | 境界トレイトの戻り値型を見直す。rcloneの終了コードをドメインへ運ばない |
| 同じ形の分岐が複数箇所へ拡散した | enumのメソッドへ集約する |

## 4. 規範実装

このリポジトリで最も規約に適合した実装を指名する。新しくコードを書く前にまずこれを読む。

- **値型**: [`crates/gitlfs-tools-domain/src/object_identifier.rs`](../../crates/gitlfs-tools-domain/src/object_identifier.rs)（49行）。
  private コンストラクタ + `生成する()`による不変条件検査（64文字の小文字16進検査）、
  検証を経由しない内部専用の`pub(crate)`経路（実測ダイジェストからの生成）、境界1箇所だけの
  生値アクセサ（`文字列表現()`）の3点が揃っている。
- **エラー分類**: [`crates/gitlfs-tools-domain/src/storage_error.rs`](../../crates/gitlfs-tools-domain/src/storage_error.rs)。
  `保管エラー`が上位層で使う分類を判別共用体で表す。期待値と実測値の不一致という同じ形の
  失敗は[`crates/gitlfs-tools-domain/src/integrity_error.rs`](../../crates/gitlfs-tools-domain/src/integrity_error.rs)の
  `整合性エラー`へ集約し、`impl From<整合性エラー> for 保管エラー`で保管操作の文脈へ昇格する。
  `thiserror::Error`によるDisplay実装は秘密情報を含まない説明文だけを持つ。
- **外部境界（domainクレート内の例外）**: [`crates/gitlfs-tools-domain/src/local_file_measurement.rs`](../../crates/gitlfs-tools-domain/src/local_file_measurement.rs)。
  domain層は本来なにも知らない層だが、アップロード検証にはローカルファイルの実測（バイト数と
  SHA-256のストリーミング計算）が要るため、domainクレート内で唯一ファイルシステムへ触れる
  外部境界としてこの1ファイルへ閉じる。

ファイル名とモジュール名は英語のsnake_case、中身の型名・関数名・フィールド名は日本語とする
（`#[path]`によるモジュール宣言は使わない）。
