## それでもAPIを既定にした理由

ひとつだけ、実害のある差があります。**`git push` が成功を返す時点で、実体がクラウドに載っているかどうか**です。

Google Drive for Desktop は同期クライアントであり、**ローカルへ書き込んだ時点で書き込み成功を返し、クラウドへの送信は非同期で後から行われます**。この基盤の観点では次が起きます。

1. `git push` の際、Git LFS が実体を保管先へ送るよう agent に求める
2. agent はマウント先へ書き込み、成功を返す
3. Git LFS は「実体は保管済み」と判断し、**Git の ref を push する**
4. 同期はまだ終わっていない。ここで回線が切れる、PCが落ちる、同期が失敗する
5. **PC B が同じコミットを clone すると、pointer はあるのに実体が無い状態になる**

Issue #2 の8節は「1件でも必要オブジェクトのuploadに失敗した場合、Git refだけが先にpushされないようGit LFSへ失敗を返す」と定めています。マウント方式ではこの約束を守れません。**成功を返した時点では、まだ何も保証していない**からです。

APIを直接叩くと、rclone が転送の完了を確認してから成功を返すので、`git push` の成功が実体の保管を意味します。設計全体が「失敗時に成功を返さない」で組み立てられているので、ここだけ緩めると全体の意味が薄れます。

## LFSキャッシュとは何か

`.git/lfs/objects/` にある、**オブジェクトの実体のローカル控え**です。

Git LFS の動きはこうです。`git add` すると、ファイルの実体は Git の通常のオブジェクトではなく `.git/lfs/objects/` へ内容から決まる名前で保存され、Git のコミットには pointer（oid とサイズだけの130バイト程度のテキスト）が入ります。`git checkout` のときは、pointer を見て `.git/lfs/objects/` から作業ツリーへ**コピー**します。

つまり同じ内容が2箇所にあります。

```text
C:\devs\Blitzdrache0\assets\terrain.heightgrid          ← 作業ツリー（実体）
C:\devs\Blitzdrache0\.git\lfs\objects\ab\cd\<oid>       ← LFSキャッシュ（同じ実体）
```

保管先（`G:` でも GitHub でも S3 でも）は**3つ目の場所**です。ローカルの2つは保管先が何であっても存在します。

## 2倍を減らす手段は2つあります

**`git lfs prune`** — 不要になったキャッシュを消します。現在のチェックアウト、stash、最近のブランチとコミットから参照されていないオブジェクトが対象です。古い版のアセットが溜まってきたらこれで回収できます。

```powershell
# 実行場所: 対象のGitリポジトリのルート
git lfs prune
```

**`git lfs dedup`** — ファイルシステムのコピーオンライトで、作業ツリーのファイルをキャッシュの複製として作り直します。**ただし対応するファイルシステムが要ります**（macOS の APFS、Windows なら ReFS）。ヘルプにも「対応していなければ失敗して終了する」と書いてあります。**NTFS では使えない**ので、あなたの環境では効きません。

## まとめ

| | 消費 |
|---|---|
| 作業ツリー | アセット容量 × 1 |
| LFSキャッシュ | アセット容量 × 1（`git lfs prune` で古い分を回収可能） |
| 保管先（`G:` / GitHub / S3） | 全履歴の全版 |

保管先だけが全履歴を持ち、ローカルは現在使っている版が中心です。GitHub の有料 LFS に切り替えても、ローカル側のこの構造は変わりません。

### 5. 地雷と環境制約

**日本語命名のRustで踏むもの**（rustスキル第8節へ収録済み）。

- 日本語ファイル名のモジュールは `#[path]` が必須（rustc E0754）。**本リポジトリはファイル名を英語の `snake_case` にしたため該当しない**
- モジュール名と型名を同じ綴りにすると衝突する（rustc E0255）。日本語命名では踏む頻度が跳ね上がる
- **関数名・メソッド名・変数名・フィールド名に大文字のASCIIを混ぜると `non_snake_case` で落ちる。** 型名は影響を受けない。`PC設定` は通るが `PC設定を読み込む` は落ちる
- `mixed_script_confusables` はキリル文字等の混入を検出するが、**簡体字の混入は検出できない**（日本語漢字と簡体字はどちらも Script=Han）。agy へ委譲したときの同形異字タイポは lint で防げず、diff での同一性確認という手順で防ぐしかない

**edition 2024 では `std::env::set_var` が `unsafe fn`** であり、`unsafe_code = "forbid"` の下では使えない。テストの環境制御を環境変数でやろうとすると詰まる。

**rclone のドキュメントとソースが食い違っている。** `lsjson --stat` は対象が見つからなくても終了コード0で `null` を返す。存在確認を終了コードで判定してはならない。また local backend は中間ディレクトリが未作成だと空配列ではなく終了コード3を返す。

**Git LFS はダウンロードで受け取った一時ファイルの所有権を奪い `rename` でリポジトリへ移す。** ドライブをまたぐ `rename` は失敗する。一時ファイルの置き場所をリポジトリ内へ固定して解決済みである。

**通常の `git clone` では LFS 対象ファイルを取得できない。** clone した時点ではまだ agent が登録されていないためである。加えて Git LFS が登録するフックが Git の clone 保護に引っかかるため `GIT_CLONE_PROTECTION_ACTIVE=false` も要る。

**`git lfs push --all origin` は復旧手段にならない。** 保管先に同じオブジェクトが既にあると、成功したと表示されるのに何も転送しない。冪等性の設計どおりだが、利用者は復旧したと誤解する。
