# コード分割規約

層の中でファイルをどう切るかを定める。層そのもの（何が何を知ってよいか）は
[アーキテクチャ.md](アーキテクチャ.md)が定める。本文書はその後段である。

## 1. 役割語彙

各クレートに置いてよいファイルの種類を、次の8役割で閉じる。「その他」の枠は無い。
分類できないコードが出たら、それは設計の誤りであり、語彙を拡張するかどうかをまず議論する。

| 役割 | ファイル名の例 | 中に書いてよいもの | 書いてはならないもの |
|---|---|---|---|
| 値型 | `オブジェクト識別子.rs` | newtype、不変条件の検査、その値に属する変換メソッド | 入出力、他の層の型 |
| ドメインモデル | `オブジェクト状態.rs` | enumと網羅分岐、状態遷移 | 入出力、外部ライブラリの型 |
| エラー分類 | `保管エラー.rs` | エラーのenumと表示、分類の判定 | 入出力、復旧処理 |
| 境界トレイト | `オブジェクト保管庫.rs` | トレイト定義と、その引数・戻り値の型 | 実装の詳細、外部プロセスの起動 |
| サービス | `資産転送サービス.rs` | ドメインの手続き。依存はコンストラクタで保持する | JSONの形式、CLI引数の綴り |
| 外部境界 | `rclone実行.rs` | 子プロセス起動、ファイル入出力、外部コマンドの引数組み立て | ドメインの判断、上位層の型 |
| コンポジションルート | `main.rs`, `組み立て.rs` | 設定の読み込み、依存の配線、起動 | ロジック本体 |
| テスト | `tests/*.rs`, 同名ファイル内の`mod テスト` | テストのみ | 本体のコード |

### 命名

- 意味を表す識別子は日本語で書く。受理条件はグローバルCLAUDE.md「日本語命名の受理条件」に従う。
- 外部仕様で固定される名前（Git LFSのJSONフィールド名、rcloneのCLI引数、TOMLのkey、
  Git設定のkey、Cargoのパッケージ名）は英語のまま保持する。
- ファイル名も日本語で書く。クレート名だけがCargoの制約により英語である。

## 2. 昇格経路

肥大化の圧力に対する逃し先を先に決めておく。判断コストをゼロにするための表である。

| 圧力（サイン） | 逃し先 |
|---|---|
| 関数が50行を超えた | 説明的な名前の関数へ分解し、原則として隣のファイルへ出す。同じファイルに残すのは10行未満の局所ヘルパのみ |
| 引数・戻り値に裸の`String`・`u64`・`PathBuf`が現れた | 値型を作って包む。個数によらない |
| `impl`ブロックが150行を超えた | 責務ごとに型を分割する |
| 1ファイルに役割が2つ以上同居した | 役割ごとにファイルを分ける |
| 1つの概念のファイルが3本以上になった | ディレクトリへ昇格し、`mod.rs`を集約点にする |
| 外部境界の型が上位層へ漏れ始めた | 境界トレイトの戻り値型を見直す。rcloneの終了コードをドメインへ運ばない |
| 同じ形の分岐が複数箇所へ拡散した | enumのメソッドへ集約する |
